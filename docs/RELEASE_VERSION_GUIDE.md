# Подготовка релиза DroneFlames PC Port

## Версия и канал

- `test` публикует пререлизы с суффиксом `-test`. Стабильный релиз имеет четыре числовых компонента без суффикса.
- Укажите номер и канал в `version_info.json`. Этот файл читают сборщики и апдейтер. Обновите заголовок в `project.godot`, `VERSION` и `WHATS_NEW` в `ui/menus.gd`, резервные строки версии в `net/github_updater.gd` и `watermark.gd`, заголовок в `Start_DroneFlames.bat` и резервные поля установщика и значения в `build.py` и `build_test.py`.
- Проверьте версии экспорта в `export_presets.cfg`. Для Windows и macOS метаданные используют числовую версию. Android требует увеличивать `version/code` при каждом обновлении пакета. Тестовый Android-пакет имеет отдельный идентификатор и отдельный постоянный ключ.
- Стабильный релиз должен быть новее уже опубликованного в `releases/latest`. Этот URL используют старые клиенты при запуске.

## Подготовка master без запуска CI

- Синхронизируйте номер стабильного релиза во всех полях выше, затем отправьте итоговый коммит с `[skip ci]` в `master`. Оставьте тег для этапа публикации.
- Когда релиз нужно собрать и опубликовать, запустите `gh workflow run build.yml --ref master` без параметра `notify_tag`. Workflow соберёт платформы, создаст тег по `version_info.json` и опубликует релиз после загрузки всех файлов.

## Перед публикацией

1. Запустите `godot --headless --script dev/test_title_icon.gd` и проверьте заголовок.
2. Убедитесь, что комплект файлов соответствует таблице в [README](../README.md). Windows Setup, Windows ZIP, macOS DMG и ZIP, архив Linux x86_64 и подписанный APK собираются в CI. Стабильный Android APK подписывается постоянным ключом своего канала.
3. Проверьте запуск и нужный сценарий обновления на каждой платформе. На Android одинаковый ID пакета, совместимая подпись и больший код версии нужны для установки поверх старого APK. При несовместимой подписи пользователю нужно сохранить данные перед переустановкой.
4. CI загружает файлы стабильного релиза в черновик и публикует его после загрузки. Проверьте комплект файлов и убедитесь, что API GitHub `releases/latest` возвращает новый тег.

## Примечания к релизу

`WHATS_NEW` в `ui/menus.gd` используется игровым окном «Что нового». Добавьте запись для нового номера в начало списка. Формат заголовка — `КАТЕГОРИЯ v<версия>: описание`.

Автоматический релиз GitHub использует сгенерированный список изменений. Каждый пререлиз, опубликованный в CI, отправляется в тестовый чат Telegram. Для ручной публикации или повторной попытки после сбоя используйте `gh workflow run build.yml --ref test -f notify_tag=v<версия>-test`.
